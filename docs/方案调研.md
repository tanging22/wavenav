# 导航面板方案调研 & 鲸鱼导航正式化路线

> 调研时间：2026-10-22 ｜ 对象：`yourdomain.com`（现在的站）→ `whale-nav`（自研替代）
> 一句话结论：**你的站是 Sun-Panel，而 Sun-Panel 已闭源；GitHub 上"可编辑导航页"只有四类方案，其中只有"后台 GUI + 数据库"这一类能完整替代它。你真正要写的不是又一个静态导航，而是 Sun-Panel 的可维护平替。**

---

## 0. TL;DR

1. `yourdomain.com` = **Sun-Panel**（Vue3 SPA + `/custom/index.css`、`/custom/index.js` 扩展点 + 备案页脚注入）。
2. Sun-Panel 作者已在 README 明写：为维持生计加入 PRO 付费功能，**项目自 v1.3.0 起转入闭源**，开源仅到旧版本。→ 这就是"必须自研"的正当理由，也是最强的立项依据。
3. GitHub 上的导航页方案分四类：**配置文件型 / 后台数据库型 / 书签管理器型 / 极简起始页型**。能"完全代替"的只有第二类。
4. 你已经有一版 `whale-nav`（零依赖 Node + 单文件前端 + JSON 存储），P0 功能约完成 60%，缺的是：多用户/角色、图库、内置应用启动器、Docker 管理器、系统状态、OpenAPI。
5. 建议路线：**先补齐 P0 自用闭环（继续 Node 也够），再决定是否升级为 Go + Vue3 单二进制正式版**。两阶段可共用 `nav.json → SQLite` 的迁移路径。

## 1. 你的站实测（yourdomain.com）

| 项 | 实测结果 |
|---|---|
| 前端 | `<div id="app">` + `/assets/index-Dca3OcbT.js`（Vite 构建），`body class="dark:bg-black"`（Tailwind） |
| 扩展点 | `/custom/index.css`、`/custom/index.js` 被主动加载 → 你在用自定义 JS/CSS 美化 |
| 页脚 | `<!-- SUNPANEL-BEIAN-START -->` 注入了 ICP + 公安备案（`粤ICP备XXXXXXXX号-X`、`粤公网安备XXXXXXXXXX号`） |
| 协议头 | `<meta name="referrer" content="never">`，移动端 viewport-fit=cover |
| 后端特征 | `/api/*` 全部回退到 index.html → 反代把 API 前缀也当 SPA 路由了（或 API 走同端口不同路径）；**做自研时别继承这个坑** |

**Sun-Panel 技术栈**（开源最后一个版本仓库结构）：`Vue3 + TS + Vite + Tailwind` 前端 / `Go + Gin + GORM` 后端（`service/api`、`service/models`、`service/router`）/ SQLite 默认，可选 MySQL、Redis / 前端构建产物由 Go 服务托管 → **单容器、单二进制**交付。
仓库：https://github.com/hslr-s/sun-panel （5.3k★，MIT，v1.8.1 发布于 2025-12-31）

### C. 书签管理器型（不是面板，是收藏夹）
[linkwarden](https://github.com/linkwarden/linkwarden) 20k（TS+PG，协同+网页归档）、[linkding](https://github.com/sissbruecker/linkding) 11k（Python，极简）、[shiori](https://github.com/go-shiori/shiori) 12k（Go 单二进制）、[gosuki](https://github.com/blob42/gosuki)（Go，多浏览器书签同步）。
→ 适合"收藏 + 检索 + 归档"，不适合当首页面板，但**可作为鲸鱼导航的"书签库"第二形态参考**。

### D. 极简起始页 / 浏览器插件型
[Bonjourr](https://github.com/victrme/Bonjourr) 2.1k、[nightTab](https://github.com/zombieFox/nightTab) 2k、[bento](https://github.com/migueravila/bento) 2.2k、[sui](https://github.com/jeroenpardon/sui) 1.6k。
→ 纯前端 localStorage 配置，无后端无账号，改起来最自由，但也最不可跨设备复用。

### 结论
- "可编辑"的三种本质：**改文件**（A）、**改数据库**（B）、**改浏览器本地**（D）。
- Sun-Panel 属于 B，且额外提供 **OpenAPI + 浏览器扩展 + JS 插件机制**这套生态，这是它比同类难替代的地方。
- 社区已有 fork 可参考：[75412701/sun-panel-v2](https://github.com/75412701/sun-panel-v2)（加书签管理）、[liandu2024/AnGe-Panel](https://github.com/liandu2024/AnGe-Panel)、[madrays/sun-panel-helper](https://github.com/madrays/sun-panel-helper)（美化）。

|---|---|---|
| 登录 + 会话 | 账号密码、记住我、登出、改密后踢会话 | ✅ 已有（scrypt + HMAC Cookie，限流） |
| 分组 + 卡片 CRUD | 拖拽排序、跨分组拖、卡片排序 | ✅ 已有 |
| 双地址（内网/外网） | 自动判断访问者网络 + 手动切换 | ✅ 已有（`lanRules` 私有网段表） |
| 图标 | 上传 / URL / emoji / 自动抓 favicon | ✅ 已有（含抓取） |
| 壁纸与遮罩 | 视频/图片、模糊、亮度、遮罩 | ✅ 已有 |

|---|---|---|
| 多用户 + 角色 | 管理/普通角色，多账号切换，数据隔离 | ❌ 单用户 |

### P2（锦上添花）
- 登录验证码（PRO）、搜索引擎自定义数量限制（PRO 放开）
- 卡片本地缓存 + 顶部加载条（v1.8.1 重点优化项）
- 分组侧边栏 JS 插件、分组独立风格、分组隐藏
- Docker 容器重启、按状态排序、`/clear` 清缓存
- i18n（40+ 语言）、PWA、浏览器扩展"新标签页"

> 结论：**P0 你已过大半；P1 是"像不像 Sun-Panel"的分水岭；P2 决定"好不好用"。**

## 4. 三条路线

### 路线 ①：继续 Node 轻量版（推荐先走）
- 在现有 `server.js`（461 行，零依赖）上补：公开模式、导出导入、图库、多用户、卡片多地址、内置应用 iframe。
- 存储从 `nav.json` 平滑升级为 **SQLite（better-sqlite3 / node:sqlite）**，仍保留 JSON 导入导出做备份。
- 成本：最小；风险：单文件会膨胀到 2k+ 行，长期维护差。
- 适合：**自用为主，够用就好**。

### 路线 ②：正式化重写（Go + Vue3，对标 Sun-Panel）
- 后端 `Go 1.22+ / Gin / GORM / SQLite`（可选 MySQL、PG），前端 `Vue3 + Vite + TS + Tailwind`，`go:embed` 打单二进制，Docker 单容器。
- 完整覆盖 P0+P1+P2，并自带**真正的 REST + OpenAPI 3 文档**、S3 兼容图床、插件钩子。
- 成本：2~4 周（按你的节奏）；收益：可长期维护、可开源、可发布、可给浏览器扩展用。
- 适合：**想做成正式项目 / 想发布**。

### 路线 ③：不自研，改用 Homarr / Dashy 定制
- Dashy 自带可视化配置编辑器，Homarr v1 拖拽 + 集成，改造成本低。
- 放弃点：备案页脚/中文生态/自定义 JS 都要另做；Homarr 需 Postgres；且你已被 Sun-Panel 审美绑住，迁移反而别扭。
- 适合：**只想尽快有个能用的，不想写代码**。

### 推荐
**①打底 → ②立项**：
1. 先用 ① 把 `yourdomain.com` 切过去跑一周（自用验证，修 UI 手感）。
2. 同时用 ② 做正式版，用 ① 的 `nav.json` 当迁移测试数据。
3. 数据格式从一开始就按 ② 的 schema 设计，别为 ① 的临时结构挖坑。

## 5. 若走路线 ②：技术设计草案

### 5.1 技术栈
| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Go + Gin（或 Echo）+ GORM | 单二进制、跨平台（amd64/arm64）、内存占用 <50MB、与 Sun-Panel 同代际 |
| 数据库 | SQLite（`modernc.org/sqlite` 纯 Go，免 CGO） | NAS 上零运维；MySQL/PG 可选 |
| 前端 | Vue3 + Vite + TS + Tailwind | 与 Sun-Panel 一致的审美与开发效率，组件生态熟 |
| 打包 | `go:embed dist/` + 多阶段 Docker | 单容器交付，`-v ./data:/app/data` 即可 |
| 采集 | `gopsutil`（CPU/内存/磁盘）、`docker/client`（容器） | 对应系统状态与 Docker 管理器 |
| 鉴权 | 会话 Cookie（HttpOnly+SameSite）+ 可选 JWT，scrypt/argon2 哈希 | 比 Sun-Panel 更规范，公开模式走独立只读路由 |

### 5.2 数据模型（最小可用）
```
user(id, username, password_hash, role[]{admin,user}, nickname, avatar, created_at)
group(id, user_id, name, slug, sort, style_json, hidden_public)
item(id, user_id, group_id, name, desc, icon_url, sort, layout_mode, cache_ttl,
     open_mode[]{self,new,window}, created_at)
item_url(id, item_id, kind[]{default,lan,wan,custom}, url, weight)   -- 替代 sun-panel 的 url/url2
icon(id, user_id, kind[]{icon,wallpaper}, path, thumb_path, width, height, size, sha256)
setting(user_id, key, value_json)         -- 壁纸/时钟/搜索/页脚/备案/logo
search_engine(id, user_id, name, url_tpl, icon, sort)
app_launcher(id, user_id, name, url, icon, size_json)  -- 内置应用 iframe
docker_binding(item_id, container_name, host)
openapi_token(id, user_id, token_hash, scope, last_used_at)
audit_log(id, user_id, action, target, ip, ua, created_at)  -- Sun-Panel 没有，加分项
```

### 5.3 路由
```
GET  /                    首页（公开或登录态）
POST /api/v1/auth/login    {username,password,remember} → session
POST /api/v1/auth/logout
GET  /api/v1/panel        聚合：settings + groups + items + urls（一次拿全，替代 N 次请求）
PUT  /api/v1/items/:id     卡片更新（部分字段）
POST /api/v1/items/reorder {moves:[{id,groupId,sort}]}
POST /api/v1/upload        素材（分类 icon/wallpaper，返回 id 而非裸路径）
GET  /api/v1/gallery       图库列表（分页/分类）
POST /api/v1/search/fetch  抓标题 + favicon（SSRF 白名单 + 超时 + 体积上限）
GET  /api/v1/system        CPU/内存/磁盘
GET  /api/v1/docker        Docker 容器列表 / POST /api/v1/docker/:id/start|stop|restart
GET  /api/v1/openauth      (OpenAPI token)  → 兼容层 /api/openapi/v1/*
```
**兼容策略**：`/api/openapi/v1/*` 做一层转译，让 Sun-Panel 浏览器扩展（Sun-Panel Helper / BE）能直接连，是"完全代替"的最快捷验证方式。

### 5.4 关键工程细节（不做会翻车）
- **SSRF**：`fetch-site` 必须禁内网/回环/云元数据地址，限 5s、限 1MB、限重定向 3 次，否则等于送人一个内网探测器。
- **上传**：白名单后缀 + magic bytes 双检、`sha256` 去重、图片重编码剥离 EXIF、视频限制大小；上传目录与静态根分离。
- **iframe**：内置应用/窗口模式会被目标站 `X-Frame-Options: DENY`、CSP `frame-ancestors` 拦；要么做反向代理转发，要么在设置里明确提示"该站不支持内嵌"。
- **Docker socket**：`/var/run/docker.sock` 挂进容器 ≈ root 权限，必须做容器白名单 + 只允许已绑定容器操作 + 普通角色禁用。
- **多用户越权**：所有查询强制 `WHERE user_id = ?`，管理角色才可跨用户；公开模式只走只读聚合接口。
- **卡片缓存**：localStorage + 版本号，服务端变更后失效（Sun-Panel v1.8.1 专门重做了这块）。
- **备份**：SQLite 用 `VACUUM INTO` 快照，导出 JSON 兼容 Sun-Panel 结构。
- **反代**：`/api` 千万别回退到 SPA（你的站现在就踩了）。

### 5.5 迁移路径（从现在的 Sun-Panel）
1. Sun-Panel 后台导出（或调 OpenAPI 拉全量卡片/分组/图标）。
2. 写一次性脚本 → 转成上面 schema 的 `nav.json`/SQLite（含图片本地化：把外链图标下载到 `data/uploads`）。
3. 双跑验证：`nav.yourdomain.com` 指新站，`yourdomain.com` 保留旧站，走一周对比。
4. 切换：DNS 改指向（`esa-dns` 可以加 `nav` 子域），旧站保留备份再下线。
